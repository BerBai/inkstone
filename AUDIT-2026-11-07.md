# Inkstone reliability audit — 2026-11-07

Scope: `themes/inkstone` only. Goal was maintainability and trust, not new
features.

## Evidence used

- Current Hugo documentation for partial return semantics and the Hugo Themes
  Gallery checklist (Context7 source: `/gohugoio/hugodocs`,
  `/gohugoio/hugothemes`).
- Generated output from `exampleSite` and fixtures on Hugo 0.128.0 and 0.161.1.
- Static assertions for HTML, local links, CSS assets, RSS, sitemap,
  multilingual alternates, shortcode markers, and malformed shortcodes.
- `html-validate` over generated HTML.
- Headless Chrome behavior checks with axe, dark mode, language switching,
  search modal, and search focus trap.

## Validation matrix

Five focused fixtures live in `tests/fixtures/`:

1. English-only minimal site.
2. Chinese-only minimal site.
3. Bilingual site on a baseURL subpath with missing translations.
4. One-page smoke test for every built-in shortcode.
5. Intentionally malformed shortcode arguments.

Each key fixture is built on both 0.128.0 and 0.161.1. The generated output is
checked for structure, links, CSS, RSS, sitemap, language alternates, shortcode
markers, performance budget, and build failures. The exampleSite also runs
`html-validate` and headless browser/a11y checks.

## Five highest-risk findings

### 1. Hugo minimum version rendered empty pages — fixed

- **Evidence:** Hugo 0.128 failed to render pages when the base template was at
  `layouts/baseof.html`; generated HTML was empty.
- **Root cause:** The template used a newer layout discovery path than the
  declared minimum supported.
- **Impact:** Every 0.128 site lost its body templates.
- **Fix:** Move the base template to
  `layouts/_default/baseof.html` and test 0.128 directly.

### 2. Root-absolute URLs broke subpath sites — fixed

- **Evidence:** Head/font/favicon/sitemap/shortcode asset URLs previously began
  with `/`; some tag links did not use language-relative URLs.
- **Root cause:** Hard-coded absolute paths bypassed `baseURL`.
- **Impact:** Sites deployed under a subpath got missing assets or escaped the
  configured base.
- **Fix:** Use `relURL`/`relLangURL` and add a bilingual subpath fixture.

### 3. Multilingual metadata and switch behavior was inconsistent — fixed

- **Evidence:** Language switch and hreflang behavior changed when translations
  were missing; language labels had no consistent fallback.
- **Root cause:** Hugo's translation collection behavior differs across versions
  and missing-language cases were not exercised.
- **Impact:** Broken or misleading alternate links for bilingual content.
- **Fix:** Explicitly filter available translations, emit `x-default` only for
  real default-language variants, and test mixed-translation output.

### 4. Unsafe shortcode inputs could fail quietly — fixed

- **Evidence:** The malformed fixture demonstrated empty or unsafe `iframe src`,
  missing AntV script paths, and missing image-compare alternatives.
- **Root cause:** Some shortcodes trusted all parameters.
- **Impact:** Invalid content reached production instead of failing a build.
- **Fix:** Add build-time `errorf` checks and a fixture that must fail.

### 5. Search modal could lose keyboard focus — fixed

- **Evidence:** Browser check exercises Tab traversal in the search dialog.
- **Root cause:** The modal had no focus containment.
- **Impact:** Keyboard users could move behind an open modal.
- **Fix:** Add a minimal Tab focus trap; validated with Playwright.

## Intentionally deferred

- **JSON-LD and OG image generation:** adding structured metadata or automatic
  image selection is a new contract, not a minimal reliability fix. It needs
  explicit image-choice semantics before release.
- **Full Lighthouse CI:** the suite already has deterministic performance,
  HTML, links, axe, and browser checks. Lighthouse adds score variance without
  addressing a current contract failure.
- **Tightening all third-party CDN loading:** every external library already has
  an explicit version param. Changing to self-hosted or integrity-hashed assets
  changes deployment and CSP behavior and should be a separate decision.
- **Douban card remote API behavior:** the card is content-specific, uses a
  third-party service, and is not exercised in the core browser matrix. Its
  minimal static markup remains stable.
